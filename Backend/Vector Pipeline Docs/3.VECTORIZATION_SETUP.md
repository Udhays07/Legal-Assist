# Document Vectorization Pipeline Setup Guide

This guide explains how to set up and use the document vectorization pipeline for semantic search capabilities.

## Overview

The vectorization pipeline automatically generates embeddings for document content using the `all-mpnet-base-v2` model (768 dimensions). Embeddings are stored in PostgreSQL using the pgvector extension.

## Architecture

### Components

1. **Embedding Service** (`app/services/embedding_service.py`)
   - Handles embedding generation using sentence-transformers
   - Manages DocumentEmbedding CRUD operations
   - Supports batch processing

2. **Document API Integration** (`app/api/document.py`)
   - Automatically generates embeddings on document create
   - Updates embeddings when document content changes
   - Deletes embeddings on document soft-delete

3. **Database Model** (`app/models/admin.py`)
   - DocumentEmbedding table with pgvector support
   - 768-dimensional vector storage
   - Relationship with Document table

4. **Batch Script** (`app/scripts/generate_embeddings_batch.py`)
   - Generate embeddings for existing documents
   - Useful for initial setup or regeneration

## Installation Steps

### 1. Install PostgreSQL pgvector Extension

```bash
# On Ubuntu/Debian
sudo apt-get install postgresql-14-pgvector

# On macOS with Homebrew
brew install pgvector

# Or build from source
git clone https://github.com/pgvector/pgvector.git
cd pgvector
make
sudo make install
```

### 2. Enable pgvector in Your Database

Connect to your PostgreSQL database and run:

```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

### 3. Install Python Dependencies (Python 3.12.0)

```bash
cd Backend

# Verify Python version
python --version  # Should show Python 3.12.0

pip install -r requirements.txt
```

This will install:
- `sentence-transformers==3.0.1` - For embedding generation (Python 3.12 compatible)
- `pgvector==0.3.2` - PostgreSQL vector extension support
- `torch==2.3.1` - Required by sentence-transformers (Python 3.12 compatible)
- `numpy==1.26.4` - Python 3.12 compatible version

**Note**: All dependencies are verified to work with Python 3.12.0. See [PYTHON_312_COMPATIBILITY.md](PYTHON_312_COMPATIBILITY.md) for details.

### 4. Run Database Migration

```bash
cd Backend
alembic upgrade head
```

This will:
- Enable the pgvector extension
- Create the `document_embeddings` table
- Create a vector similarity search index

### Batch Processing Existing Documents

For documents created before this feature was deployed:

```bash

python -m app.scripts.generate_embeddings_batch

# Process only 10 documents (for testing)
python -m app.scripts.generate_embeddings_batch --limit 10
```

### Manual Embedding Generation

You can also generate embeddings programmatically:

```python
from app.services.embedding_service import create_or_update_embedding
from app.core.database import SessionLocal

db = SessionLocal()
try:
    # Generate embedding for a document
    embedding = create_or_update_embedding(
        db=db,
        document_id=document_id,
        content="Your document content here"
    )
    print(f"Embedding created: {embedding.document_id}")
finally:
    db.close()
```

## Model Information

### all-mpnet-base-v2

- **Dimensions**: 768
- **Model Size**: ~420MB
- **Performance**: Excellent quality for semantic search
- **Speed**: ~2000 sentences/second on CPU
- **License**: Apache 2.0 (Open Source)
- **Best For**: Legal documents, Q&A, semantic search

On first use, the model will be automatically downloaded (~420MB). This happens once and is cached locally.

## Vector Search (Future Implementation)

The embeddings are stored with a vector similarity index. To perform semantic search:

```python
from sqlalchemy import text

# Example: Find similar documents using cosine similarity
query_embedding = generate_embedding("search query text")

similar_docs = db.execute(
    text("""
        SELECT d.id, d.title, d.content,
               1 - (e.embedding <=> :query_embedding) as similarity
        FROM documents d
        JOIN document_embeddings e ON d.id = e.document_id
        WHERE d.deleted_at IS NULL
        ORDER BY e.embedding <=> :query_embedding
        LIMIT 10
    """),
    {"query_embedding": query_embedding}
).fetchall()
```

## Performance Considerations

### Model Loading
- Model is loaded once on first use (singleton pattern)
- Subsequent calls reuse the cached model
- Initial load takes ~2-3 seconds

### Embedding Generation
- ~50-200ms per document (depends on content length)
- CPU-based (no GPU required)
- Can be optimized with batch processing

### Database Storage
- Each embedding: ~3KB (768 floats)
- Index size: ~10% of total embedding data
- Query performance: <10ms for similarity search

## Troubleshooting

### Issue: Model download fails

```bash
# Set cache directory
export TRANSFORMERS_CACHE=/path/to/cache
export SENTENCE_TRANSFORMERS_HOME=/path/to/cache
```

### Issue: Out of memory during batch processing

```bash
# Process in smaller batches
python -m app.scripts.generate_embeddings_batch --limit 100
```

### Issue: Slow embedding generation

- Ensure you're not running in debug mode
- Consider using GPU if available (install `torch` with CUDA)
- Use batch processing for multiple documents

### Issue: pgvector extension not found

```sql
-- Check if extension is available
SELECT * FROM pg_available_extensions WHERE name = 'vector';

-- If not available, install pgvector on your system first
```

## Configuration

### Change Embedding Model

To use a different model, edit `app/services/embedding_service.py`:

```python
MODEL_NAME = "sentence-transformers/all-mpnet-base-v2"  # Change this
EMBEDDING_DIMENSION = 768  # Update dimension accordingly
```

Then update the migration and model:

```python
# In migration file
embedding = Column(Vector(NEW_DIMENSION), nullable=False)

# In app/models/admin.py
embedding = Column(Vector(NEW_DIMENSION), nullable=False)
```

### Disable Automatic Embedding

To disable automatic embedding generation, comment out the calls in `app/api/document.py`:

```python
# create_or_update_embedding(db, doc.id, final_content)
```

## Monitoring

### Check Embedding Coverage

```sql
-- Count documents with embeddings
SELECT 
    COUNT(DISTINCT d.id) as total_documents,
    COUNT(DISTINCT e.document_id) as documents_with_embeddings,
    COUNT(DISTINCT e.document_id)::float / COUNT(DISTINCT d.id) * 100 as coverage_percentage
FROM documents d
LEFT JOIN document_embeddings e ON d.id = e.document_id
WHERE d.deleted_at IS NULL;
```

### Check Embedding Freshness

```sql
-- Find documents with outdated embeddings
SELECT d.id, d.title, d.updated_at as doc_updated, e.updated_at as embedding_updated
FROM documents d
JOIN document_embeddings e ON d.id = e.document_id
WHERE d.updated_at > e.updated_at
AND d.deleted_at IS NULL;
```
